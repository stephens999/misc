Introduction

This file takes a closer look at the objective function of the asymmetric fastICA approach from fastica_asymmetric_03.Rmd based on asymmetric binary priors, and implements a simple Newton optimizer that performs many starts in parallel to optimize the weights \(w\) for a fixed prior.

The prior \(g_0\) is binary with probabilities \((1-p, p)\) and atoms \((y_0, y_1)\) chosen so that \(g_0\) has mean 0 and variance 1: \[y_1 = \sqrt{\frac{1-p}{p}}, \qquad y_0 = -\sqrt{\frac{p}{1-p}}.\] The prior \(g\) is then \(g_0\) scaled by a factor \(c\), so the effective atoms are \(cy_0\) and \(cy_1\). The default scale is \(c = c_\text{golden} = 2/(1+\sqrt{5})\) and the default residual variance is \(\sigma^2 = c\). The condition \(\sigma^2 = c\) ensures that the method is equivalent to fastICA (logcosh) when \(p=0.5\). The choice \(c=c_\text{golden}\) ensures that prior variance plus residual variance is 1 (\(c^2 + c=1\)).

When \(p = 0.5\) and \(c = \sigma^2\) the objective and updates reduce to standard fastICA (with \(g(t) = \log\cosh\)): the posterior mean becomes \(c\tanh(x)\) and the posterior derivative becomes \(c(1-\tanh^2(x))\), and the c factors have no effect under the final \(\ell_2\) normalisation.

My idea is that maybe we can get away with running this for just a few values of \(p\), rather than optimizing over \(p\) explicitly. Indeed, fastICA itself is already quite good at finding both balanced binary sources (near \(p=0.5\)) and sparse binary sources. But it finds the former as maxima over the objective and the latter as minima, which does not make it easy to compete a sparse binary source against a balanced binary source. This is potentially important because fastICA has a tendency to combine sparse binary sources into a single balanced binary source; if we had an objective function in which genuine sparse binary sources score better than combinations then this would be helpful to avoid this. When \(p\) is smaller (eg 0.1) then maybe the objective function can find both balanced and sparse sources as local maxima, with the sparse sources getting scored higher than combinations of sources? We will see…

Objective Function

The per-observation contribution to the objective is \[\log Z(x;\, p, c, \sigma^2) = \log\!\left[(1-p)\exp\!\left(\frac{2x\,cy_0 - (cy_0)^2}{2\sigma^2}\right) + p\exp\!\left(\frac{2x\,cy_1 - (cy_1)^2}{2\sigma^2}\right)\right]\] with \(y_1 = \sqrt{(1-p)/p}\), \(y_0 = -\sqrt{p/(1-p)}\), and the full objective is \(J(w) = \sum_i \log Z(x_i)\).

Applying the identity \(\log(e^a + e^b) = \tfrac{a+b}{2} + \log 2 + \log\cosh\!\bigl(\tfrac{b-a}{2}\bigr)\) gives a clean decomposition: \[\log Z(x;\,p,c,\sigma^2) = \gamma x + \delta + \log 2 + \log\cosh(\alpha x + \beta)\] where \[\alpha = \frac{c}{2\sigma^2\sqrt{p(1-p)}}, \quad \beta = \frac{1}{2}\log\frac{p}{1-p} - \frac{c^2(1-2p)}{4\sigma^2 p(1-p)}, \quad \gamma = (1-2p)\,\alpha.\] So the objective is log cosh of a shifted-and-scaled \(x\), plus a linear term. At \(p=0.5\): \(\alpha = c/\sigma^2\), \(\beta = \gamma = 0\), recovering \(\log\cosh(\alpha x) + \text{const}\) (standard fastICA, up to a constant).

The linear term (which enters for \(p \neq 0.5\)) might suggest that the expected objective function increases with the mean of the source (in cases where we allow a non-zero mean). However, this is not the case because it is balanced by the log cosh term (see plots later below).

c_val   <- 2 / (1 + sqrt(5))
s2_val  <- c_val
p_objs  <- c(0.5,0.4,0.33,0.25,0.1,0.05,0.01)
cols    <- palette.colors(length(p_objs), palette = "Okabe-Ito")

log_Z_vec <- function(x, p, c, s2) {
  y1  <- sqrt((1 - p) / p);  y0 <- -sqrt(p / (1 - p))
  ey0 <- c * y0;  ey1 <- c * y1
  lp0 <- log(1 - p) + (2*x*ey0 - ey0^2) / (2*s2)
  lp1 <- log(p)     + (2*x*ey1 - ey1^2) / (2*s2)
  m   <- pmax(lp0, lp1)
  log(exp(lp0 - m) + exp(lp1 - m)) + m
}

Expected objective by source type

Since we have default values for \(c,\sigma^2\) we will write the objective function \(Z\) for a given \(p=p_\text{obj}\) as \(Z(x; p_\text{obj})\).

A natural question is: what is the expected value of \(\log Z(x; p_\text{obj})\) for a binary source with weights \(p_\text{source},1-p_\text{source}\) (or \(p_\text{s},1-p_\text{s}\) for brevity). In many of our experiments we allow the source to have non-zero mean, \(\mu\), so we consider binary sources that are parameterized by \(p_\text{s}, \mu\). Since we constrain the second moment to 1, the variance is \(1 - \mu^2\), and these constraints determine the locations of the atoms, which are at \[a_0 = \mu - p_s\,d, \quad a_1 = \mu + (1-p_s)\,d, \quad d = \sqrt{\frac{1-\mu^2}{p_s(1-p_s)}}.\]

Expected value curves for fixed \(p_\text{obj}\)

We now examine the expected value of \(\log Z(x;p_\text{obj})\) for different \(p_\text{obj}\) in a range from 0.5 to 0.05. For a binary source with mean \(\mu\) and weight \(p_\text{source}\) we can easily compute the expectation from the atoms above. We plot \(E[\log Z]\) as a function of \(\mu\) for several values of \(p_\text{source}\). A curve that peaks above its Gaussian baseline is a source detectable by this objective; how far the peak sits from \(\mu = 0\) shows how much the intercept is contributing. The behavior if we fix \(\mu=0\) is also apparent from these plots.

For \(p_o=0.5\) (fastICA), at \(\mu=0\), the sparse binary sources are below the Gaussian baseline whereas the balanced binary sources are above the Gaussian baseline. While the sparse binary source curves do go above the baseline near \(\mu=-1\), this is a rather restricted part of the space that we would probably have to deliberately search (eg by initializing the intercept near that location) to find it? (I’m not sure about this; might be worth thinking more about.) The maxima are all the same height showing that this objective function does not prefer sparse sources to balanced sources, which accords with intuition since \(p_o=0.5\).

In contrast, for \(p_o=0.25\), almost all the sources (except the vary rarest ones) are above the Gaussian baseline at \(\mu=0\) and even more so if you allow \(\mu\) to be estimated away from 0. Obviously for finding truly sparse sources it would pay to use a smaller \(p_o\), but this plot suggests that \(p_o=0.25\) might be a good general purpose choice.

By the time you go down to \(p_o=0.01\) the ability to find more common sources, even 0.1, might be quite restricted.

Based on these curves I am inclined to go with running the method for a range of \(p\) such as \(p=0.25,0.05,0.01\).

# Expected log Z for a binary source with mean mu, second moment 1
# (so variance = 1 - mu^2); atoms are mu +/- scaled y0/y1.
E_logZ_binary_shifted <- function(p_source, mu, p_obj, c, s2) {
  d  <- sqrt((1 - mu^2) / (p_source * (1 - p_source)))
  a0 <- mu - p_source       * d
  a1 <- mu + (1 - p_source) * d
  (1 - p_source) * log_Z_vec(a0, p_obj, c, s2) +
       p_source  * log_Z_vec(a1, p_obj, c, s2)
}

Maximizing over mu

We can also show all curves on the same plot, either by fixing \(\mu=0\) or by taking the max of each curve over \(\mu \in (-1, 1)\): \[\max_\mu\, E_{p_s,\mu}[\log Z(x)] = \max_\mu\left[(1-p_s)\log Z(a_0) + p_s\log Z(a_1)\right].\] The Gaussian baseline is similarly \(\max_\mu\, E_{N(\mu,\,1-\mu^2)}[\log Z(x)]\). The utility of showing the max is maybe limited because for many curves the max is at the degenerate solution (ie the intercept). Possibly it would be more useful to look at the location of the non-generate max? Anyway, I show this for now, but focus discussion on the plot for \(\mu=0\) (left below).

We see for \(\mu=0\) that the curve for \(p_o=0.25\) is above the Gaussian baseline for a range of \(p_s\) in about 0.2 and above. And the curve for \(p_o=0.05\) is above the baseline for many rare sources (maybe not for \(p_s\) very close to 0 though). This suggests that even fixing \(\mu=0\) and running the method for \(p_o=0.25,0.05\) might be able to find a wide range of binary sources.

# Max over mu in (-1, 1) via grid search (objective can be non-unimodal).
E_logZ_binary_maxmu <- function(p_source, p_obj, c, s2, n_grid = 201) {
  mu_grid <- seq(-1 + 1e-4, 1 - 1e-4, length.out = n_grid)
  max(sapply(mu_grid, function(mu)
    E_logZ_binary_shifted(p_source, mu, p_obj, c, s2)))

Update functions

# Newton update (ica-hessian approximation).
# U is (n.comp) x n (whitened data).
# W is (n.comp) x n_starts (one weight vector per column).
# P = t(U) %*% W is n x n_starts (source estimates).
# When p = 0.5 and c = s2 this is identical to standard fastica_update.
binary_newton_update <- function(U, W, p = 0.5, c = 2 / (1 + sqrt(5)), s2 = c) {
  y1  <- sqrt((1 - p) / p)
  y0  <- -sqrt(p / (1 - p))
  ey0 <- c * y0
  ey1 <- c * y1

  P   <- t(U) %*% W                              # n x n_starts

  lp0 <- log(1 - p) + (2*P*ey0 - ey0^2) / (2*s2)
  lp1 <- log(p)     + (2*P*ey1 - ey1^2) / (2*s2)
  m   <- pmax(lp0, lp1)
  e0  <- exp(lp0 - m);  e1 <- exp(lp1 - m)
  pi1 <- e1 / (e0 + e1)                          # n x n_starts

  Mx  <- (1 - pi1) * ey0 + pi1 * ey1             # posterior mean
  Mpx <- pi1 * (1 - pi1) * (ey1 - ey0)^2 / s2   # dM/dx

  W <- U %*% Mx - sweep(W, 2, colSums(Mpx), "*")
  sweep(W, 2, sqrt(colSums(W^2)) + 1e-15, "/")
}

# Gradient update (no Hessian correction; equivalent to hessian = "none" in ebproj).
binary_gradient_update <- function(U, W, p = 0.5, c = 2 / (1 + sqrt(5)), s2 = c) {
  y1  <- sqrt((1 - p) / p)
  y0  <- -sqrt(p / (1 - p))
  ey0 <- c * y0
  ey1 <- c * y1

  P   <- t(U) %*% W                              # n x n_starts

  lp0 <- log(1 - p) + (2*P*ey0 - ey0^2) / (2*s2)
  lp1 <- log(p)     + (2*P*ey1 - ey1^2) / (2*s2)
  m   <- pmax(lp0, lp1)
  e0  <- exp(lp0 - m);  e1 <- exp(lp1 - m)
  pi1 <- e1 / (e0 + e1)                          # n x n_starts

  Mx  <- (1 - pi1) * ey0 + pi1 * ey1             # posterior mean

  W <- U %*% Mx
  sweep(W, 2, sqrt(colSums(W^2)) + 1e-15, "/")
}

# Objective J(W) = sum_i log Z(x_i, g, s2), returned as a vector of length n_starts.
binary_objective <- function(U, W, p = 0.5, c = 2 / (1 + sqrt(5)), s2 = c) {
  y1  <- sqrt((1 - p) / p)
  y0  <- -sqrt(p / (1 - p))
  ey0 <- c * y0
  ey1 <- c * y1

  P   <- t(U) %*% W                              # n x n_starts

  lp0 <- log(1 - p) + (2*P*ey0 - ey0^2) / (2*s2)
  lp1 <- log(p)     + (2*P*ey1 - ey1^2) / (2*s2)
  m   <- pmax(lp0, lp1)
  colSums(log(exp(lp0 - m) + exp(lp1 - m)) + m)  # length n_starts
}

# matrix version of r1 fastica
# U is (n.comp+1) x n (whitened data plus intercept).  
# W is (n.comp+1) x n_starts (one weight vector per column).
# P = t(U) %*% W is n x n_starts (source estimates).
fastica_update = function(U, W) {
  P  <- t(U) %*% W          # n x n_starts: source estimates
  G  <- tanh(P)
  G2 <- 1 - G^2
  W  <- U %*% G - sweep(W, 2, colSums(G2), "*")
  # Add epsilon (1e-15) to prevent 0/0
  sweep(W, 2, sqrt(colSums(W^2)) + 1e-15, "/")
}
